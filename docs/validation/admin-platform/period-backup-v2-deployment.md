# QF-05：备份 v2 原生与部署验收

日期：2026-11-18。本批范围为 v2 的实际 celld 验证与兼容部署，QF-05 整体仍为 in_progress。

## 原生证据

`python3 scripts/verify_body_evidence_native.py` 使用独立 celld 项目/卷、生产租户控制类、CJS Daemon/BodyAgent、实际 Docker Engine 和本地模型 HTTP 夹具。仅临时生成的测试入口替换租户类，注入模拟月末与执行覆盖，创建一份隔离关账单；真实执行随后产生晚到调整。生产 src/deploy 未注册该测试入口，不能把此覆盖声明视为已认证的生产执行清单。

先保存 v1，再创建 period 数据和 v2。验收明确要求 v1 无 period 表、v2 包含一份关账单和非空调整，随后通过现有私有归档 API 下载、宿主机 CLI 独立恢复到新 SQLite。源摘要、账目汇总、关账/回执/调整关系校验通过，已有目标拒绝覆盖。真实 Fleet 重启后，旧 v1 与新 v2 原文均保持一致；旧 v1 仍能独立恢复。

夹具中的准入有效期由边界值 300 秒改为 240 秒，避免调用端/服务端时钟微差造成超过服务上限；生产有效期校验没有放宽。原用量、丢回执、Host 事实、长身份 Agent、旧 fork 和实际价格快照联合回归继续通过，没有付费模型请求。

## 构建与开发验收

严格控制面 187 项测试、325 模块构建与原生联合验收通过。兼容升级已构建部署，首轮安全排空重启保留 119 条原任务及规格、原 Drain。升级后的服务导出目录和两个实际租户快照，下载到受限宿主机目录并独立恢复；其中历史 UNCERTAIN 及 outbox 仍保持原状态。

开发环境没有创建 period 数据，仍按 v1 导出；v2 正向数据证据来自上述隔离 celld。没有创建开发费率、激活、执行任务或线上最终账单。备份恢复仍为 `operationalResume=DISABLED`，没有覆盖在线卷。

第二轮安全重启完成，119条任务及规格保留。三份新归档经双Gateway读取与宿主机副本逐项一致；原用量/空价格/账目、三个入口历史UNCERTAIN/pending、Host观察、容量目录/epoch和4/4 Prometheus回归全部通过。实际开发归档明确仍为v1且无period表；没有借测试夹具启用线上关账。
