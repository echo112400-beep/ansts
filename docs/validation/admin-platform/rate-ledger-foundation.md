# QF-04：费率、快照与不可变账目内核

> 本文保留内核阶段记录。后续服务/执行接线和部署状态见 [服务验收](rate-ledger-service-acceptance.md)。

日期：2026-11-17。QF-04 状态为 **in_progress**。本记录验证隔离内核，不代表开发环境已启用费率、自动账目或硬配额。

## 已实现

- `RateCatalog`：不可变内部 credit-subunit 费率版本，严格字段白名单、全局管理员权限、CAS、摘要、幂等与事务审计。零费率与未知费率分别使用显式零和 null，没有供应商默认价格。
- `TenantRateStore`：可信目录适配器提供费率后显式激活；执行前固定完整价格及归属快照，包含未激活的 null。已有用量绑定禁止首次补绑价格；目录模板和元数据修改不改写在途/历史快照。
- `UsageCostLedger`：仅接受同权威 UsageInbox 已接收的原始事件，校验来源摘要和固定归属/费率版本，保存原事件、接收时间、精确分数、pending 原因及内容摘要。重复投影返回同一记录，不重复累计。
- 精确计算以 BigInt 完成，分子/分母及舍入结果有显式上限。按 UTC 日、成本中心版本、费率激活版本和维度先累加精确分数再统一舍入，支持 FLOOR/CEIL/HALF_EVEN。未知数量不补零，provider 精确匹配供应商、请求模型与返回模型，缓存分拆与全量输入互斥。
- 不完整汇总返回已知子总额及原因，完整总额为 null。未投影、open、隔离、缺响应、未知池/价格/归属及有界读取截断均影响完整性；跨租户不可达不能成为完整零值。固定 `final=false`，不冒充关账结果。

## 验证

`npm run test:control`：严格检查及 **146 项测试通过**，其中本批新增 18 项。`npm run build`：**319 模块构建通过**。测试使用真实原生 SQLite 文件和事务、真实 BodyUsageJournal 与 UsageInbox，不以 JSON SQL 模拟器验证原子性。

覆盖费率/激活权限、CAS 和幂等冲突、审计失败事务回滚、null 与旧价格固定、元数据变更后的显式重激活要求、迟到补绑拒绝、重复入账、上下文冲突、聚合后舍入、UTC 日界、缓存不重复计价、未知旧执行、模型不匹配、缺响应与溢出拒绝。关闭并重新打开原生数据库后，费率、激活、null 快照和账目保持一致；仅删除隔离测试中的派生投影，再从原始事件和固定快照重建，结果及历史 pending 内容一致。

测试中的费率是隔离夹具，不是生产配置或实际供应商价格。没有付费模型请求、开发任务执行或现有数据修改。
