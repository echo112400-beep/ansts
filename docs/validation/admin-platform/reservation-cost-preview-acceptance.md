# QF-05 预留可信成本预览

内部准入服务通过 POST /internal/v1/tenant-control/admission-cost-preview 按预留 ID 读取结果。租户权威核对已认证的 Body 终止回执、固定执行身份、接受的连续用量、账目摘要及原归属。未终止或证据、数量、归属与价格不完整时，返回明确的待核算原因。请求不更新预留阶段或预算占用。

带价格的 SQLite 隔离验证中，跨 UTC 午夜的同一执行分别贡献 1/2 和 3/2 个 credit 子单位。不同执行在同一天及同一归属、费率激活和维度下的精确贡献可以进入同一个桶。预算入账策略须先确定该桶的整额如何分摊，再执行结算和释放。来源未闭合或账目未投影时不给出候选金额，SQLite 重开及重放后版本和成本桶一致。

运行 `python3 scripts/verify_body_evidence_native.py`，真实 celld 重启后仍能读取已认证终止的预留。历史执行缺少价格快照，携带零成本的请求仍返回 PRICE_SNAPSHOT_MISSING；目录凭据返回 401，后续超额申请仍返回 BUDGET_QUOTA_EXCEEDED。探针先清除结算顺序表超限夹具，再注入 Body 发现上限夹具，以便分别验证两类上限。本次原生验收退出码为 0。

控制面 196 项、全仓类型检查、lint 和 334 模块构建通过。当前生产接线仍为 shadow，未执行部署。

## 新准入执行的价格固定

仅带固定执行身份的新预留具有绑定时定价资格。在 Body 校验执行身份、进入计量绑定后，租户权威再核对预留的启动授权、有效期、资源和归属。价格快照与用量绑定同事务写入。并发绑定保留首个结果；写入失败两处均回滚；重新激活费率后，旧执行重放仍读到原费率。旧预留、迟到补传和 UNCERTAIN 的首次绑定保留待核算状态。

原生探针由真实 BodyAgent 启动隔离执行，使用本地模型端点并按已激活费率生成 CPU、内存、槽位和模型的成本投影。预留成本预览完整，Fleet 重启后与原响应一致，历史无价预留仍占用预算。控制面 198 项、全仓类型检查、lint 和构建通过。本轮未部署，预算分摊、入账与释放继续验证。

## 可信成本入账与预算释放

准入服务凭据与全区域 SRE 管理身份调用 POST /internal/v1/tenant-control/admission-settle-cost，提供预留 ID、版本、成本预览摘要和幂等键。租户权威在写入事务中重新计算成本。一笔提交对同一成本桶入账的整额等于累计精确量在本次提交前后的舍入差额。单个预留获得的整额随同桶提交顺序分配，桶的累计整额与提交顺序无关。已入账金额按实际用量 UTC 日归属，月预算汇总该月各日。旧 SETTLED 记录继续按预留创建日计入预算。

提交在同一事务中保存累计桶、日入账额、预留 SETTLED 状态、幂等回执、审计和容量出站事件。待核算执行继续占用原估算。控制面测试覆盖跨午夜和月末、两个半单位累计为一个整额、成本版本冲突和出站写入失败时回滚。真实 celld 验证并发重复请求只入账一次，客户端金额字段被拒绝，新申请可用额度等于预算减去剩余预留和实际入账，超出 1 个单位的申请被拒绝。Fleet 重启后返回原回执，备份含原始结算状态，并通过离线恢复。

控制面 199 项、类型检查、lint 和构建通过。本轮未部署。准入服务结算仍需显式调用，自动晚到调整与月末关账继续推进。
