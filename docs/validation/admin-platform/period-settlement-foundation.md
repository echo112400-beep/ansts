# QF-05：月结与晚到调整内核验收

日期：2026-11-18。任务状态 **in_progress**。本批提供隔离可验证的关账内核，尚未接入生产关账路由、执行清单认证或预算释放。

## 实现

新增 `PeriodSettlement`。首期财务关账使用严格 `YYYY-MM` UTC 月份；资源仍按 UTC 日分段和费率/归属/维度聚合后舍入，预算原有 UTC_DAY/UTC_MONTH 不变，避免同一费用按两种关账日历重复出账。

预览读取已接收原始事件与固定价格账目，校验事件身份、序号、窗口、资源关闭、provider 请求/响应和价格完整性。只有可信执行清单覆盖所有相关 attempt、周期结束且无未结预留/缺失项时，才可原子保存不可变关账单和幂等回执。未投影、未知价格/数量、缺响应、隔离、未覆盖 attempt 及跨期未结预留均阻止最终关账。

关账单冻结 source/adjustment 水位、账目摘要、校验时的流状态、覆盖声明与计价桶；校验输入整体摘要可从保留的 basis 重算。CAS 拒绝预览后数据变化，重试与重复关闭返回原单据；原始事件、费率和准入状态不改写。整租户关账要求 SRE 和完整租户地域权限，Viewer 仅可在完整授权范围读取。

## 晚到与冲突

已关闭周期水位之后的旧周期用量，生成确定性事件 ID 的独立调整，关联原关账摘要、原事件和价格，分配到接收时不早于原周期下一月的开放周期。重放不重复生成，已关闭单据保持原文。

差额计算采用 `round(原精确量 + 已结晚到量 + 本期晚到量) - round(原精确量 + 已结晚到量)`，防止逐事件或逐月独立舍入造成重复计费。未结的更早调整周期会阻止依赖其舍入基数的后续关账；缺价格的晚到记录仍 pending。关闭后出现 source 冲突，会追加关联 attention；即使投递钩子尚未运行，预览也能发现未路由的晚到/冲突并阻止关账。

内核有签名游标、10000 行/调整读取上限、1200 个关账周期、8 MiB 单据上限及历史 JSON 长度保护；超限拒绝，不返回截断的完整金额。

## 修复的源端月界问题

回归先复现 `USAGE_CLOCK_REGRESSION`：provider 回调在零点后先落盘，而资源 cursor 仍在前一天，后续 UTC 分段会试图追加更早时间戳。

`BodyUsageJournal` 现于 provider 请求/响应落盘前，先原子保存已跨越的 UTC 日界资源分段。当天普通回调不额外切段；晚到响应在资源已关闭时不重新分配资源。现有事件前缀、签名内容和序号不重写。测试覆盖月界 token 按响应月份归属、请求跨零点、未知响应、进程重建以及文件保存失败后的完整回滚。既有失效事件不通过改写历史来伪装修复。

## 下一步与边界

`SettlementCoverage` 当前只是内部适配器参数，测试用隔离执行清单构造。它不是已认证的生产证据，不能直接接受浏览器 `complete=true`；没有覆盖声明时内核拒绝关账。下一批需接入可信 Scheduler/Body 完整执行清单和覆盖水位，并明确历史未计量任务的缺失覆盖。

还需完成可信实际成本与舍入分摊、SETTLING→SETTLED/预算释放、在线鉴权 API 与自动晚到钩子的同事务接线、人工正负调整、真实取消/失败流程、双 Gateway 并发及服务重启故障验收。现有财务备份 v1 未包含新增 period 表，服务启用前必须升级格式并验证旧 v1 兼容；本批没有在生产实例化这些表。QF-05 保持进行中，硬配额和最终账单未启用。

全仓库 lint 的既有扩展名检查问题未在本批处理；局部严格检查不代表全仓库检查通过。
