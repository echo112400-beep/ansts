# 系统拓扑详情页

目标：SRE 从系统状态进入全系统拓扑，发现异常后选择组件，读到采集证据、实例、容量与上下游关系。沿用现有控制台视觉，不生成不存在的监控指标。用户已授权实现，未提供单独设计稿。

## 展示与交互

- `/system` 可直接访问；现有系统状态导航进入同一页面。
- 首屏展示整体健康、探测覆盖、Fleet/执行器实例和执行槽位，以及最近成功采集时间。异常先于常规明细展示。
- 拓扑覆盖控制台/Nginx、双 Gateway、三节点 celld Fleet、两台 Body Daemon、RustFS、Prometheus、Grafana、兼容 Body 代理；解释 Fleet 中的 Scheduler/Gateway/Body/Harness/Tunnel 状态对象以及 Daemon 本地执行、日志/结果回传路径。
- GitHub OAuth、DeepSeek 和容器 Engine 显示配置与验证边界，不把“已配置”冒充“健康”。连接线表示配置/代码中的调用关系，不宣称链路逐跳验证成功。
- 选择节点高亮直接依赖，显示职责、实际探测地址、HTTP 状态、延迟、时间、容量/运行指标与健康原因。实例表可搜索、按异常筛选，并能选择同一节点。
- 默认每 15 秒刷新，允许暂停、手动刷新。采集接口失败保留上次快照和时间并给重试；单个节点失败仍返回部分系统快照。无配置/无权限/初次加载分别显示。
- 移动端按层级纵向展示，选中详情可就地查看，页面不横向溢出。

## 数据与权限

全局拓扑仅 SRE_ADMIN；普通角色保留 Gateway/Scheduler 基础连通性，不能读取内部地址、跨租户任务、资源账本。管理员界面也不输出任务 ID、服务密钥、结果、Journal 原文或未筛选上游 JSON。

槽位/CPU/内存来自 Daemon reservation ledger，明确是“可分配/预留”，不是宿主 CPU 利用率。Fleet 内存和对象数来自 `/state`。监控平台健康与采集目标健康分开展示。当前观测到 Prometheus 四个目标为 401/404，应显示降级及证据，不能画全绿。RustFS 就绪不代表已有 EC:4 或生产容灾证明。

## 验收

鉴权与字段筛选、节点超时/HTTP 失败/部分结果、Daemon drain/恢复、Prometheus 抓取失败、未探测依赖与正常状态分别测试。生产构建通过；真实部署后桌面1440×900、手机390×844验证拓扑选择、筛选、暂停/刷新、深链接和错误恢复。独立视觉与只读 UX 走查。
