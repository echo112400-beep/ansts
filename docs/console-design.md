# Console 设计讨论

本文保留原 SRE 故障处置场景及演示原型的设计依据。完整平台管理面的范围、角色与功能以 [Console 管理面功能设计](./console-management-design.md) 为准；下文的 SRE 优先和演示参数限定在原场景。

## 已确认的设计方向

- 基于现有 Console，重新梳理信息架构、关键操作流程和视觉层级。
- 首要用户为正在值班、需要快速定位和处理故障的 SRE；平台管理员和只读观察者为次要用户。需求冲突时优先保证故障处理效率。
- 贯穿评审的场景：某区域请求延迟突然升高，值班人员从 Console 找到受影响范围、判断原因，并安全完成处置。
- 首页优先呈现异常区域、影响范围、延迟与错误率、受影响请求和近期变更；健康区域保留简要状态，成本分析进入独立页面。
- 主导航按总览、区域与资源、任务、变更与操作记录组织；WAL、分片迁移、Drain 等技术能力进入对应对象的详情页。
- 诊断明确区分已观测事实与疑似原因，展示证据、数据时间和缺失信息，允许原因未确定。
- 有权限的值班 SRE 可在 Console 内完成生产处置。生产变更先展示目标、影响范围和恢复办法；扩大影响范围或难以恢复的操作需要额外审批，具体分类待定。
- 区域、时间范围和选中对象在诊断页面之间保留，并可通过链接分享调查视角。历史视角明确标示，执行前核对目标当前状态。
- 刷新失败时保留最后一次成功的数据并显著展示更新时间；无法验证当前状态时阻止提交生产变更，恢复连接后重新验证操作条件。
- 审批按影响分类：预设边界内且具备恢复路径的操作由值班人员确认；跨区域、超出预设影响范围或无法恢复的操作需另一位有权限者批准。审批绑定目标和参数，参数变化需重新审批。
- 生产操作形成持续跟踪的记录，区分请求提交、执行成功与服务恢复，展示进度、结果和处置后指标；关闭页面后可找回。失败时展示已完成步骤与可用恢复动作。
- 第一版交付可交互设计原型，先覆盖区域延迟升高的完整流程：发现异常、调查证据、确认处置、审批与执行、验证恢复。覆盖正常处置、数据过期、无权限、审批被拒和执行失败。
- 请求延迟、错误率、流量、资源压力和近期变更使用同一时间轴，支持从异常指标进入相关对象；证据展示来源与更新时间，缺失数据明确标示。
- 服务恢复要求：受影响区域的延迟和错误率在指定观察窗口内持续满足既定服务目标，且无新的关联告警。目标未配置或观测数据不足时标示待验证。
- 原型使用可重复切换的模拟场景，始终标示演示数据，生产操作仅模拟执行；真实接口接入另行设计。
- 视觉采用桌面优先、信息紧凑且层级清晰的运维界面；状态同时使用文字、图标和颜色表达。验收通过场景任务检查使用者能否准确说明影响范围、证据、操作目标和最终结果。

## 首个场景与演示配置

- 某区域内单个网关异常，通过 Drain 排空该网关；展示关联流量和剩余容量，并保留证据不足、暂不操作的出口。
- 可编辑演示目标：P95 延迟低于 300ms，错误率低于 1%，连续观察 5 分钟。这些数值不是生产默认值。
- 剩余容量充足且影响局限于单区域时允许单人确认 Drain；跨区域影响需要额外审批。必要条件缺失或无法验证时阻止执行。容量是否充足由模拟场景提供明确的检查结果，不推定生产容量阈值。
- OPERATOR 发起操作，另一位 SRE_ADMIN 审批；VIEWER 只读。提供演示身份切换，禁止自批。
- 审批等待期间目标状态变化需重新验证；影响范围变化则原审批失效。目标或参数变化也需重新审批。
- Drain 开始后若部分失败，停止自动推进，展示实际状态；重试或恢复前重新验证。只有明确具备恢复能力的步骤才展示恢复动作，其余提供人工处置说明，不承诺一键撤销。

## 交付与验收

- 仓库内可独立打开的 HTML 原型；浅色、中性灰为主，桌面优先。
- 提供场景切换、角色切换和完整操作记录，始终标示演示数据。
- 覆盖正常处置、证据不足、数据过期、无权限、跨区域审批、审批被拒、审批失效、执行部分失败与恢复待验证。
- 通过场景任务检查使用者能否准确说明影响范围、证据、操作目标和最终结果。
- 布局、间距及组件样式等可逆细节由实现时按上述原则确定；不扩展生产接口与实际生产操作。

## 现有能力与拟新增能力

- 现有网关 Drain 可将目标网关标记为排空并发出替换通知；这不证明完整的流量迁移与服务恢复流程已经实现。
- 现有 Canary rollback 没有区域参数，会重置全部槽位和任务绑定；首个原型不将它描述为区域回滚。
- 现有 HITL 审批用于任务 STAGED_COMMIT，不等同于通用运维审批。
- 本次通用运维审批、影响验证、操作跟踪和恢复验证按拟新增交互设计展示，不宣称真实后端已支持。

## 状态

Q1–Q21 与最终范围均已由用户确认。已实现 [独立 HTML 原型](./ansts_console_design.html)。
目前未形成同时满足难以逆转、需要解释背景且存在实质取舍条件的架构决策，因此暂不创建 ADR。

## 原型使用

- 用现代浏览器直接打开 HTML，无需安装依赖或启动后端。
- 从“调查异常”进入证据与处置前检查，选择“准备 Drain”核对目标和恢复限制。
- 跨区域场景使用林（OPERATOR）发起，再切换陈或周（SRE_ADMIN）审批；管理员发起时也不能自批。
- “推进模拟执行”和“推进观察 1 分钟”显式推进演示时间；指标再次超标会重置连续观察窗口。
- 场景切换保留原操作快照；目标已有未完成操作时阻止重复提交，可在操作记录中继续跟踪。
- 操作记录保存在当前浏览器本地，并支持导出 JSON。浏览器禁止本地存储时会提示会话限制。
- 调查链接包含区域、窗口、对象和场景，不包含身份或操作档案；接收者需拥有同一 HTML 文件，记录不会跨设备同步。

## 已验证与限制

- 39 项浏览器交互检查通过，覆盖执行与恢复分离、连续观察窗口、自批拦截、双人审批、拒绝、审批失效、历史与过期数据拦截、容量和证据不足、部分失败重试、缺少服务目标、刷新后记录恢复、调查链接、区域上下文、导航位置与存储失败时的导出提示。
- 验证桌面 1440px、窄屏 390px 与 720px 等效放大布局，无页面级横向溢出。
- 项目 lint 通过；内联脚本语法检查通过。
- 独立视觉评审 8/10；已修正旧提示与恢复结论冲突，补充调查图例并压缩小屏顶部区域。恢复观察置于可展开事件历史旁，优先展示当前结果。
- 独立 UX 走查完成首页进入调查、阅读证据并寻找处置入口的路径；发现导航保留滚动位置导致主动作不在视口。已修正为进入目标页时回到顶部，主 Agent 浏览器检查验证。独立走查未覆盖 Drain 提交后的完整流程，该部分由主 Agent 的交互检查覆盖。
- 使用轻量按钮反馈、对话框进入和首次内容进入动画，支持减少动态效果偏好。
- 所有指标均为演示数据；不接入生产接口、不发布站点、不改变原有 Console 入口。通用运维审批和恢复验证仅为拟新增交互。
