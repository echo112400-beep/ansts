实施已启动，目录与观测基础已上线。领域能力继续按 37 项任务推进。

## A 已确认的范围

| 能力 | 首期目标 | 后续阶段 |
| --- | --- | --- |
| 配额与成本 | 资源额度、用量计量、内部成本分摊 | 外部支付与正式账务另立项目 |
| 配置发布 | 版本、预检、双人审批、灰度、回退 | 基础设施变更另走部署流程 |
| 算力市场 | 内部容量池、配额内借用、公平排队 | 外部撮合、运行抢占后置 |
| 多地域治理 | 目录、驻留策略、放置模拟、接入门禁 | 供应商和地域确定后真实接入 |

内部成本采用版本化 credit。缺少价格或用量时显示待核算。

## B 四个模块如何协作

```flow LR
租户配额 -> 准入预留: 原子校验
准入预留 -> 容量池: 申请物理资源
地域策略 -> 容量池: 限制允许位置
容量池 -> 任务执行: 授权与版本凭证
任务执行 -> 用量账本: 持久投递
用量账本 -> 成本分摊: 版本费率
配置发布 -> 准入预留: 已审批策略
```

执行状态不确定时保留占用。超时不能作为释放或重跑的依据。

## C 用户会获得什么

| 页面 | 可完成的工作 | 关键证据 |
| --- | --- | --- |
| 租户与 FinOps | 看额度、改策略、查成本、导出 | 用量来源、费率版本、账本水位 |
| 配置治理 | 看差异、审批、灰度、暂停与回退 | 不同审批身份、每目标实际版本 |
| 内部算力分配 | 申请空闲容量、查队列和授权 | 唯一宿主机、真实占用、释放确认 |
| 地域治理 | 登记目录、设驻留、模拟放置 | 来源、身份、证据时效、排除原因 |

界面沿用现有 hrui 风格。冲突时保留输入，失败时保留上一份数据。

## D 按什么顺序建设

| 阶段 | 任务数 | 交付结果 |
| --- | --- | --- |
| M0 基础 | 6 | 租户、权限、审计、持久化与观测 |
| M1 配额成本 | 8 | 计量、账本、关账、影子与试点准入 |
| M2 配置发布 | 7 | 独立审批、目标应用、灰度与回退 |
| M3 容量分配 | 6 | 公平排队、授权绑定与安全回收 |
| M4 地域治理 | 6 | 目录、策略、模拟与接入门禁 |
| M5 综合验收 | 4 | 故障注入、浏览器、隔离部署与试点 |

M2、M4 可在基础完成后分线推进。容量分配依赖配额准入。

## E 上线需要哪些证据

| 检查 | 必须证明 |
| --- | --- |
| 配额 | 双网关争抢不超发，断联不绕过限制 |
| 成本 | 重放不重复入账，跨期和晚到事件可复核 |
| 发布 | 自己不能审批，缺少生效证据时暂停 |
| 容量 | 同机不重复计数，失联占用不再次分配 |
| 地域 | 未知驻留被拒绝，模拟不触发真实执行 |
| 部署 | 隔离卷与端口，重启后账本和占用一致 |

仅页面或 API 返回成功，不能解除未接入状态。

## F 后续实施前的输入

内部费率维护人、成本中心归属、试点额度和独立审批人需要落实。

地域、供应商、远端身份、复制设施和 RPO/RTO 目标仍待确定。

这些输入不阻塞规划和模拟开发。真实地域验收保持待配置。
