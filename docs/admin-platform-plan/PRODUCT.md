# 后台能力产品方案

状态：规划稿；本文描述目标行为，不能作为已上线能力说明。

## 1. 使用者与首期目标

平台管理员维护租户额度和内部费率，运维人员安全发布配置，团队负责人查看成本归属和容量使用。首期解决“谁能使用多少、成本由谁承担、配置是否真正生效、容量如何分配、任务允许落在哪里”。

内部成本单位采用版本化 `credit`，界面同时显示原始用量。它是内部核算单位，不是钱包余额。首期仅进行 showback（展示分摊），真实扣费、支付、税务、开票和外部市场交易均后置。

多地域先交付目录、约束和模拟能力。供应商、具体地域与复制设施未确定；界面显示“未配置”“未验证”，不生成演示地域或假健康状态。

## 2. 配额与内部成本

入口沿用 `/manage/tenants`，新增租户详情 `/manage/tenants/[tenantId]`，页签为“额度与预算 / 用量 / 成本分摊 / 策略历史”。成本中心汇总位于 `/manage/finops`。

额度包括并发执行数、CPU 核、内存 MiB、队列任务数；内部预算按 UTC 日或月设置。界面明确额度单位、计量窗口、更新时间、已使用、已预留、可用、待核算，金额和资源不混为一个百分比。软阈值先告警，硬阈值限制新增准入；降低限额不会中止现有任务，只阻止超额新增。

管理员编辑时查看旧值、新值、影响租户、预计阻塞任务与原因。修改提交带版本，冲突时保留输入并展示最新版本。阈值、预算、费率的变化进入审计；预算变化只影响新准入估算，已运行任务保留原始价格快照。不得用模型自动降级代替明确策略；首期模型切换需要独立授权。

成本详情支持成本中心、租户、资源池、任务、attempt、模型和时间窗口筛选。任务重试按每次真实执行分别计量，再汇总到原任务。失败或取消产生的真实消耗仍保留；未确认结束的执行显示“待核对”，不会因超时自动返还额度。共享宿主机的物理容量只计一次。

计量分开显示：分配 CPU 核时、分配内存 GiB 时、slot 时长、供应商返回的输入/输出 token。分配量不标成真实 CPU 利用率。缓存 token 等供应商特有维度必须有证据才能细分，未知价格或缺失 token 显示待核算，不能记作零。

月结流程为“预览 → 校验缺失项 → 关账 → 导出”。包含未结 attempt 或未定价数据时，先生成临时汇总，不能标为最终关账。更正用独立调整记录，保留原始账单与费率版本。导出包含单位、价格版本、时间窗、成本中心归属版本和完整性标记，并处理 CSV 公式注入。

## 3. 配置发布

入口 `/manage/configs`，详情 `/manage/configs/[bundleId]`。列表显示版本、作用域、状态、审批人、灰度进度和最近有效版本。详情包括结构化差异、校验结果、影响范围、审批记录、每目标执行结果。

流程：创建不可变版本 → schema/语义校验 → 影响预检 → 提交审批 → 另一位管理员批准 → 小批发布 → 检查运行结果 → 扩大范围。发布开始时冻结目标清单、策略快照与内容摘要；审批后改内容会生成新版本并重新审批。草稿、审批、发布状态分开展示。

灰度验证包含目标读取版本 ACK、实际配置摘要、健康检查和相关错误率；HTTP 200 不能替代生效证据。缺失观测数据时暂停，不视作成功。部分目标失败显示确切目标、原因与恢复动作，不将部分成功汇总成“已发布”。

回退选择已验证版本，创建一个新的前进版本；重新校验和审批，保留完整链路。首期发布范围采用显式字段白名单，例如调度权重、非秘密运行参数与告警阈值。密钥仅保存引用；身份授权、数据库迁移、镜像/基础设施部署、跨地域复制、计费费率不走任意 JSON 发布。

审批至少两位不同的 GitHub 数字身份。若当前只有一位管理员，显示“缺少独立审批人”，不能自己批准，也不静默绕过。紧急绕过不在首期范围。

## 4. 内部算力市场

入口 `/manage/capacity`，产品名“内部算力分配”。汇总展示容量池、租户保障份额、空闲可借额度、排队需求及分配记录，不显示买卖报价或支付按钮。

管理员登记容量池和物理宿主机，再将已验证容量授权给租户。团队在硬配额范围内申请额外空闲容量，提交 CPU、内存、时段、优先级、地域约束与用途。系统返回接受、排队或拒绝及具体原因；必须同时满足租户配额、可用物理容量和地域策略。

首期只支持即时、尽力而为的空闲借用，不承诺未来时段的容量预订。采用带权主导资源公平排队，团队可看到自己的排队原因和等待时长，不能读取其他租户的任务内容。优先级不能绕过硬配额。借用不会生成第二份执行成本；只改变容量权益来源。

到期回收尚未使用的授权。任务已启动或状态不确定时，保留对应容量，待确认结束再释放；首期不强杀、不迁移、不自动抢占。主机失联时停止新增分配，并隔离既有占用，避免将失联容量当作空闲再次分配。

## 5. 多地域治理

入口 `/manage/federation`，包含“地域目录 / 驻留策略 / 放置模拟 / 证据与演练”。地域属性：供应商类型、国家或司法辖区、故障域、执行能力、端点身份、容量来源、健康证据时间和连接状态。空列表提供接入说明，地图不是验收必需品。

管理员先定义允许地域、禁止跨界数据类型、所需模型与恢复目标，再用任务元数据模拟放置。输出候选集、每项排除原因、策略版本及缺失证据。`US/EU/APAC` 等宽泛标签不能替代具体驻留要求；司法辖区未知时拒绝受约束放置。

首个真实接入仅对新任务选择地域，排空时停止新准入。在运行与 UNCERTAIN 任务不自动切换地域或重跑。代码先具备适配器接口和模拟测试，界面持续显示真实接入门槛，直到供应商、远端身份、存储、网络与执行环境通过验收。

灾备卡分别显示备份、恢复、复制延迟和 RPO/RTO 的“目标 / 最近实测 / 未验证”。同一开发机上的多个 Cell 不算多个地域或独立故障域；没有恢复演练不能标记“灾备就绪”。自动跨域故障切换是后续独立项目。

## 6. 权限与交互规范

继续以服务端验证的 GitHub 数字 ID、租户范围和角色授权。头像、登录名、Profile 仅用于展示。首期沿用现有角色，不直接添加后端尚不认识的财务角色。

| 操作 | VIEWER | OPERATOR | SRE_ADMIN |
| --- | --- | --- | --- |
| 查看授权范围的额度、用量与配置状态 | 允许 | 允许 | 允许 |
| 发起自己租户的容量需求 | 禁止 | 允许 | 允许 |
| 修改额度、费率、容量池或地域策略 | 禁止 | 禁止 | 允许，需原因与版本 |
| 创建配置版本、发起发布 | 禁止 | 禁止 | 允许 |
| 审批自己发起的配置发布 | 禁止 | 禁止 | 禁止 |
| 审批他人的配置、回退 | 禁止 | 禁止 | 允许 |
| 关账、调整、批量导出 | 禁止 | 禁止 | 允许，遵守授权范围 |

上表为拟议权限，需要对照现有 RBAC 实现再落地。所有写权限在服务端执行；越权请求不因知道 tenantId 而成功。后续引入 FINOPS 等职责时，另做权限版本迁移。

延续 `ui/hrui` 纸白、蓝色强调、四阶文字、Inter/JetBrains Mono、分组导航、紧凑表格、侧边抽屉。没有独立 Figma 输入，沿用现有页面与验收截图作为样式基线。数字表头标明单位，状态同时用文本和图标表示，避免仅靠颜色。

统一处理：首次空态、权限不足、未接入、过期数据、请求失败、处理中、部分成功、版本冲突。错误保留上一份数据并标明时间，写入失败保留表单。危险动作确认框展示对象、影响与原因；提交后能查操作记录。键盘可完成流程，窄屏使用单列详情和可访问表格滚动。

## 7. 产品验收门槛

每项功能需同时通过持久化重启验证、服务端权限验证、真实业务链路测试和浏览器流程测试，才能解除“未接入”状态。只实现页面或一个成功响应不算上线。

配额与成本验收必须证明并发不超发、重放不重复入账、跨日不丢预留、关账可复核。配置必须证明不同操作者审批、每目标真实生效和故障暂停/回退。容量必须证明共享宿主机不重复统计、失联不超卖、运行授权不误回收。地域必须证明未知驻留被拒绝、模拟不触发执行、缺少基础设施时不会启用真实路由。
